測試腳本

每一條都對應規格的一條規則。右下角的「測試面板」可以切換開關與時間，用來驗證條件分支。

A 帳號與登入

  1. 登出後，用 nobody@other.com 送出 → 仍然進到驗證碼那一步，訊息為「若此信箱為本租戶的成員，驗證碼已寄出」——不透露該信箱是否存在。
  2. 承上，輸入畫面顯示的驗證碼 → 失敗，訊息與驗證碼打錯時完全相同。
  3. 用 lin@smalltree.example 送出，記下驗證碼，等倒數跑完按「重新寄送」，再輸入舊的那一組 → 舊碼已失效，被擋下；輸入新碼才能登入。
  4. 登入成功後登出，再用同一組驗證碼登入 → 驗證碼單次使用，已失效。
  5. 連續輸錯 5 次 → 鎖定 15 分鐘，期間即使輸入正確的碼也不放行。
  6. 寄出驗證碼後 60 秒內按「重新寄送」 → 按鈕停用並顯示剩餘秒數。
  7. 「我收到邀請信」→ 姓名留空送出 → 擋下。填妥後送出 → 不需設定密碼即加入；列出四項效果：狀態轉已加入、姓名寫入成員列表、取得老師角色並綁定檔案、邀請連結立即失效。
  8. 我的帳號 → 模擬閒置逾時 → 導回登入頁；重新登入後回到原本那一頁。
  9. 我的帳號 → 介面語言切 English → 左側選單與頁標題變英文；切「日本語」時只有部分字串被翻譯，其餘退回中文。

B 首頁

  1. 首頁 → 下一堂顯示倒數；正在上課的場次標「進行中」。
  2. 測試面板把時間切到「今天全部上完之後」 → 今天的課全部轉為已完成；還沒點名的會進待辦，而結束超過 24 小時的則轉為逾期、從待辦消失（需管理後台解鎖）。
  3. 測試面板切到「週日」 → 顯示「今天沒有課」並帶出下一堂的日期。

C 課表與報到

  1. 課表點任一堂 → 看得到課名、時間、場地、人數、狀態與學員名單；名單沒有任何金額或訂單資訊。
  2. 點一堂還沒開始超過 30 分鐘的課 → 報到按鈕停用，提示「開課前 30 分鐘才開放登記」。把測試面板時間調到開課前 10 分鐘 → 開放登記。
  3. 登記後再改一次 → 下方「變更紀錄」多一筆，記錄誰、何時、由什麼改成什麼。
  4. 用報到碼核銷：輸入名單上的 4 位數 → 該學員標記為已報到；輸入亂碼 → 查無此報到碼。
  5. 找一堂結束超過 24 小時的課 → 整份名單唯讀，提示需由管理後台解鎖。

D 可授課時段

  1. 點週日任一格 → 擋下：超出店家營業時間。
  2. 點平日 12:00 那一列 → 擋下：此時段為店家休息時間。
  3. 點一個已被預約的格（實心橘） → 擋下：已被學員預約，需先由管理後台改派或取消。
  4. 切到「表單列表」 → 同一份資料的另一種編輯介面，兩邊改動互相同步。

E 休假與額度

  1. 申請一段已經有課的期間 → 送出前就列出衝突場次清單；送出後狀態為待審核。
  2. 在有衝突的情況下按「核准」 → 被擋下，要求先改派或取消那些場次。
  3. 核准一筆沒有衝突的休假 → 額度卡的「已用」增加、「待審佔用」減少；可授課時段那一天被扣除。
  4. 撤回或駁回待審的申請 → 額度不扣抵。取消一筆已核准的休假 → 額度回補。
  5. 測試面板把「休假額度模組」關掉 → 額度卡整組消失，申請流程照走。
  6. 申請超過剩餘額度的天數 → 預設不擋，標記「超額」交審核者決定。

F 課後回饋與學員歷程

  1. 課後回饋 → 開一堂 7 天內完成的課 → 可填；缺席的學員標示「不需填寫」。
  2. 開一堂完成超過 7 天的課 → 唯讀，提示需管理後台解鎖。
  3. 測試面板把「等級模組」關掉 → 回饋表單的「建議等級」欄位整個不見，只剩評語。
  4. 填一個建議等級並儲存 → 明確提示「已送出建議，學員等級尚未變更，需管理後台核可」。
  5. 學員歷程搜尋「趙允薇」 → 查無此學員——她在本租戶存在，但沒上過你的課，所以查不到。
  6. 點任一學員 → 看得到上過幾堂、每堂出席狀態、我過去的回饋；沒有金額。
  7. 測試面板把「顯示學員聯絡資料」打開 → 才出現電話與家長聯絡方式，預設是關的。

G 我的資料與統計

  1. 個人資料改自我介紹並儲存 → 預設存檔即生效。測試面板打開「個資修改需審核」再存一次 → 進入待審狀態，前台仍顯示舊內容。
  2. 授課統計切本月／上月／全期間 → 堂數與時數跟著變；畫面上找不到任何金額欄位。
  3. 我的帳號 → 按「試著開啟管理後台網址」 → 回「找不到」，不是「沒有權限」。
